Plan: Multi-Order Dispatch
The Core Problem
Right now Dispatch.order_id is a hard non-nullable FK to one customer order. However, DispatchItem.order_item_id already links each line item to its own OrderItem (which knows its own order_id). The DB already supports multi-order items at the item level — the only real blocker is the single order_id on the Dispatch header.

DB Change Required (1 migration, unavoidable)
What	Why
Make Dispatch.order_id nullable	A dispatch route serving 3 customers has no single "order" — the orders are derived from its items
This is one ALTER TABLE dispatch ALTER COLUMN order_id DROP NOT NULL statement. Everything else is a code change.

Backend Changes
models.py

Dispatch.order_id = Column(Integer, ForeignKey(...), nullable=True) — remove nullable=False
schemas.py

DispatchBase.order_id: Optional[int] = None
main.py

Endpoint / Function	Change
create_dispatch	Accept order_id = None; derive all affected order IDs from dispatch_items → order_item → order_id; after saving, call update_order_statuses for each unique order found in items
update_dispatch_status	Same — derive order IDs from dispatch items, not from dispatch.order_id
update_order_statuses	No change needed — already takes a single order_id, just needs to be called once per unique order
GET /dispatches list column	Show all unique order codes derived from items
